## 1. 平台是做什么的

**诚翼畅联数据平台**是「终端全生命周期管理（TEM）」一期建设中的 **通信费用管理看板**。它把以下五类 Excel 原始数据：

| 数据类型 | 典型来源 | 系统内表名 |
|---------|---------|-----------|
| 运营商用量 | 联通/移动用量报表 | `raw_usage` |
| 运营商账单 | 账单清单 + 账单明细 | `raw_billing_list` / `raw_billing_detail` |
| 企业资产 | 客户资产台账 | `raw_asset` |
| 企业人员 | HR / 通讯录 | `raw_employee` |
| 月度事件 | 入职、改号、离职、维修等 | `raw_event` |

经过 **字段标准化 → 跨表匹配 → 规则引擎**，汇总成一张 **月度结果表** `fact_tem_monthly`（按「客户 + 项目 + 账期 + 服务号码」一行），再在看板上做费用分析、超套分析、异常预警、成本中心分摊、事件运营等。

**EMOS 模块**（Enterprise Management Operating System）是另一套能力：基于历史样板项目（强生、礼来、GE 等）的 **组件库与匹配规则**，帮助新项目快速生成「落地配置包」和 AI 审查报告。它与 TEM 账务数据 **共用平台入口**，但用途偏 **项目售前/交付配置**，不是每月账单必经步骤。

## 2. 如何登录与启动

### 2.1 启动应用（IT 或首次部署人员）

```powershell
cd 项目根目录
pip install -e .
tem init-db
streamlit run "app/诚翼畅联数据平台.py"
```

浏览器访问：`http://localhost:8501`（或 IT 提供的内网地址）。

### 2.2 登录

1. 打开平台后会看到 **登录页**。
2. 输入 **用户名** 和 **密码**，点击「登录」。
3. **默认管理员账号**（首次 `tem init-db` 且库中无账号时自动创建）：
   - 用户名：`admin`
   - 密码：`admin`
   - **首次登录后请让管理员修改密码并创建个人账号。**

### 2.3 两种角色

| 角色 | 能做什么 |
|------|---------|
| **普通用户** | 首页、数据导入/导出、六项分析看板、EMOS 三个模块 |
| **管理员** | 上述全部 + 账号管理、数据删除、项目差异维护 |

登录后，侧边栏底部会显示当前用户名与角色，可点击 **「退出登录」**。

## 3. 界面导航说明

左侧导航分为 **四组**（带底框分隔）：

| 分组 | 模块 | 谁常用 |
|------|------|--------|

| **系统** | 账号管理*、数据删除* | 管理员 |

\* 仅管理员可见。

### 3.1 侧边栏「客户 / 项目 / 账期」选择器

**位置**：首页左侧侧边栏（进入子页面后仍保留）。

**作用**：为所有 **分析类页面** 和 **数据导出** 提供统一的查询范围。选择后写入会话状态，各分析页自动按该范围取数。

**原理**：
- 客户、项目来自 `config/settings.yaml` 配置 + 库内已有数据；
- 账期来自该客户/项目下已导入并成功生成 `fact_tem_monthly` 的账期列表；
- 若账期为空，说明尚未导入或未跑规则引擎，需先到 **数据导入** 页操作。

**操作步骤**：
1. 在侧边栏「客户」下拉框选择客户（如 `johnson · 强生`）。
2. 选择「项目」（如 `work-phone · 工作手机项目`）。
3. 选择「账期」（如 `202604`）。
4. 进入任意分析页即可看到该范围数据。

## 4. 核心概念：数据是怎么流转的

理解以下流程，有助于知道「某一步失败了该查哪里」。

```
Excel 文件
    ↓ ① 上传 / 放入 data/raw/
    ↓ ② 自动识别（列名 + 文件名）→ 五类 raw 表
    ↓ ③ Import Gate 校验（必填列、主键重复等）
    ↓ ④ 规则引擎 build → fact_tem_monthly
    ↓ ⑤ 看板查询 / Excel 导出
```

### 4.1 主键与范围

所有分析都以四维为主键：

**客户ID + 项目ID + 账期 + 服务号码**

- **客户ID**：如 `johnson`（强生）、`lilly`（礼来）
- **项目ID**：如 `work-phone`（工作手机）、`ipad-esim`
- **账期**：六位年月，如 `202604` 表示 2026 年 4 月
- **服务号码**：手机号，系统会做格式标准化（去空格、统一前缀等）

### 4.2 五类原始表各自含义

| 表 | 粒度 | 说明 |
|----|------|------|
| raw_usage | 按月、按号码 | 流量、通话、短信 |
| raw_billing_list | 按月、按号码 | 账单汇总行（实际应收等） |
| raw_billing_detail | 按月、按号码、按科目 | 账单明细（一级科目、上网费等） |
| raw_asset | 按客户/项目全量 | 号码对应资产、套餐基准价、使用人 |
| raw_employee | 按客户全量 | 员工 ID、部门、Cost Center |
| raw_event | 按客户/项目，带事件月份 | 改号、入职、离职、维修等 |

用量/账单必须带 **账期**；资产/人员/事件通常是 **项目级全量快照**，导入时仍要选账期（供规则引擎关联当月事件）。

### 4.3 规则引擎在算什么

`fact_tem_monthly` 每一行 = 一个号码在当月的 **费用 + 用量 + 人员组织 + 异常标签** 的综合画像。主要规则包括：

| 规则类型 | 含义 | 举例 |
|---------|------|------|
| **超套 C01–C06** | 实际应收 > 标准套餐金额 × (1 + 5%) | 套餐 187 元，账单 250 元 → 超套 |
| **零用量 Z01–Z04** | 几乎无流量/通话/短信但仍计费 | 离职未销号 |
| **高用量 H01–H04** | 流量或通话超过阈值 / P95 | 异常大流量 |
| **漫游** | 账单明细含国际/港澳台漫游科目 | |
| **增值业务** | 非白名单增值科目有费用 | |
| **离职后计费** | 员工已离职但当月仍有账单 | |
| **跨表缺失** | 账单号码在资产/人员表找不到 | 资产缺失、人员缺失 |
| **事件** | 当月改号、未闭环事件等 | |

阈值在 `config/rules.yaml` 中配置，一般运营人员 **无需修改**，有问题联系管理员或开发。

### 4.4 Import Gate（导入闸门）

导入前/导入时会跑 **Import Gate**：
- 检查必填列是否映射成功（如「服务号码」）
- 检查主键是否重复
- 未映射列会警告

当前模式为 **strict**：有 **error** 级问题会 **阻断写库**。因此若导入失败，应先看 Gate 报告里的错误信息，而不是重复点导入。

## 5. 标准月度作业流程（推荐 SOP）

以「强生 work-phone 202604 月」为例，推荐顺序如下：

| 步骤 | 页面/动作 | 负责人 | 产出 |
|------|----------|--------|------|
| 1 | 准备 5 类 Excel | 客户/运营商 | 原始文件 |
| 2 | **数据导入** → 选客户/项目/账期 → **导入前预检** | 数据运营 | 预检通过 |
| 3 | **数据导入** → **开始导入**（勾选「入库后跑规则引擎」） | 数据运营 | fact 表有数据 |
| 4 | **首页** 选客户/项目/账期，核对核心指标 | 对账专员 | 指标合理 |
| 5 | **异常清单** / **超套分析** 逐类排查 | 对账专员 | 异常处理清单 |
| 6 | **费用统计** / **成本中心分摊** 与客户确认 | 客户经理 | 分摊表 |
| 7 | **数据导出** 生成 Excel 月报 | 数据运营 | 交付客户 |
| 8 | （可选）测试环境用 **数据删除** 清库重导 | 管理员 | — |

## 6. 模块一：诚翼畅联数据平台（首页）

### 6.1 功能

月度 **指挥舱**：展示当前所选客户/项目/账期的核心 KPI。

### 6.2 操作

1. 在侧边栏选好 **客户 / 项目 / 账期**。
2. 若三项齐全，首页显示：
   - **账务核心**：月度账单总额、分析号码数、人均账单、超套金额
   - **用量画像**：超套/零用量/高流量/高通话号码数

3. 若提示「请在左侧选择客户/项目/账期」→ 说明尚未选择或库中无数据。

指标来自数据库视图 `v_monthly_summary`，底层聚合 `fact_tem_monthly`。  
**没有导入 + build，首页无数据。**

### 6.4 何时使用

- 每月对账第一眼：总量是否正常
- 向客户汇报前的「一页纸摘要」

## 7. 模块二：数据导入

### 7.1 功能

拖拽 Excel/CSV，自动识别数据类型，校验后写入数据库，可选立即生成月度结果表。

### 7.2 详细操作步骤

#### 第 1 步：选择客户 / 项目 / 账期

| 字段 | 说明 | 示例 |
|------|------|------|
| 客户 | 来自系统配置的下拉 | `johnson · 强生` |
| 项目 | 该客户下项目；也可在下方文本框 **手动输入新项目 ID** | `work-phone` |
| 账期 | 六位数字 YYYYMM | `202604` |

> 账期即使导入资产/人员/事件也 **必填**，供规则引擎标记「数据月份」。

#### 第 2 步：上传文件

- 支持 `.xlsx` / `.xls` / `.csv`
- **可多选**，一次上传多份文件
- 系统自动识别每个文件/sheet 属于：用量 / 账单 / 资产 / 人员 / 事件

**识别原理**：
1. **列名匹配（优先）**：如出现「一级科目」→ 账单明细；「事件类型」→ 事件表
2. **文件名兜底**：如文件名含「清单」「list」→ 账单清单；「明细」「detail」→ 账单明细
3. **跳过辅助 sheet**：如「事件字典」「_下拉选项」不会入库

#### 第 3 步：识别预览

上传后立即显示表格：
- 每个文件的识别结果
- 识别依据（列名 / 文件名）
- 可展开查看每个 sheet 的列名列表

**若显示「未识别」**：检查 Excel 表头是否与客户模板一致，或联系管理员在 `config/field_maps.yaml` 增加列名别名。

#### 第 4 步：导入前预检（强烈建议）

1. 点击 **「🔍 导入前预检」**。
2. 系统只跑 Import Gate，**不写库、不复制文件**。
3. 查看结果：
   - ✅ 预检通过 → 可正式导入
   - ❌ 有错误 → 看 Gate 报告，修正 Excel 后重新上传

**常见预检失败原因**：

| 现象 | 原因 | 处理 |
|------|------|------|
| 错误含 `服务号码` / `['服务号码']` | 账单/用量表没有可映射的手机号列 | 将列名改为「号码」「手机号码」「服务号码」等，或联系管理员加别名 |
| 主键重复 | 同一账期同一号码多行 | 去重或核对源文件 |
| 未映射列过多 | 列名与系统不认识 | 对照 `data/samples/` 模板 |

#### 第 5 步：开始导入

1. 勾选 **「入库后跑规则引擎」**（默认开启，建议保持）
2. 勾选 **「导入后清空看板缓存」**（默认开启）
3. 点击 **「🚀 开始导入」**
4. 查看：
   - 各表入库行数
   - 文件处理报告（落地路径在 `data/raw/...`）
   - Import Gate 校验报告

**导入成功后**：
- 原始文件归档到 `data/raw/{类型}/{客户ID}/{项目ID}/[{账期}/]`
- 侧边栏账期列表会出现新账期
- 可到首页、分析页查看

### 7.3 五类文件字段要求（简表）

完整模板见 `data/samples/`。最低要求：

**用量**：服务号码、账期、（流量或通话或短信至少一项）  
**账单清单**：服务号码、账期、实际应收（或计费应收）  
**账单明细**：服务号码、账期、一级科目、实际应收  
**资产**：服务号码、标准套餐金额（超套规则基准）、联系人/邮箱/员工编号等  
**人员**：员工ID、部门、Cost Center、员工状态  
**事件**：原始号码、事件类型、事件动作、开始时间、事件状态  

> Excel 中 **不需要** 填客户ID、项目ID——系统按你在页面上选的值自动注入。

### 7.4 原理补充

- **同范围重导**：同一客户+项目+账期再次导入会 **覆盖** 该范围旧数据（先删后写）
- **strict 模式**：Gate 报 error 则整批不写库，避免脏数据进入看板

## 9. 模块四：费用统计

### 9.1 功能

从 **部门 / 成本中心 / 号码** 三个维度看费用构成。

### 9.2 操作

1. 侧边栏选好范围。
2. 打开 **费用统计**。
3. 查看三个表格：
   - **按部门 / BU**：号码数、员工数、实际应收、超套金额
   - **按成本中心**：同上，带 Cost Center
   - **按号码 TOP 20**：单号码费用与用量概览

### 9.3 原理

直接对 `fact_tem_monthly` 聚合；部门/Cost Center 来自 **人员表与资产表匹配** 结果。若人员表缺失，Department/CostCenter 可能为空。

### 9.4 使用场景

- 客户财务按 BU 分摊前的核对
- 找出费用最高的号码

## 10. 模块五：用量分析

### 10.1 功能

查看 **流量、通话、短信** 总量与分布，识别零用量/低用量号码。

### 10.2 操作

1. 顶部指标卡：总流量、总通话、短信、人均值、零/低用量号码数
2. **流量 TOP 20** / **通话 TOP 20** 表格
3. **零用量清单**：当月几乎无用量但仍可能计费的号码

### 10.3 原理

- 用量来自 `raw_usage` 标准化后的字段（流量 GB、通话分钟）
- 「零用量」「低用量」由规则引擎在 build 时打标（`是否零用量`、`是否低用量`）

### 10.4 使用场景

- 排查「僵尸号」「长期不用但仍出账」
- 与异常清单中的「零用量但计费」交叉验证

## 11. 模块六：超套分析

### 11.1 功能

分析 **实际应收超过标准套餐** 的号码（超套）。

### 11.2 操作

1. 查看汇总：超套号码数、超套金额合计、平均超套率
2. **超套清单**：明细（来自视图 `v_overpackage_list`）
3. **部门 / 成本中心超套排行**

### 11.3 原理

```
超套金额 = max(0, 实际应收 - 标准套餐金额)
是否超套 = 实际应收 > 标准套餐金额 × (1 + 5%)   # 默认 5%，见 config/rules.yaml
超套率 = 超套金额 / 标准套餐金额
```

**标准套餐金额** 主要来自 **资产表** 的「标准套餐金额」字段——若资产数据不准，超套结果会偏差。

## 12. 模块七：异常清单

### 12.1 功能

汇总所有 **规则引擎判定的异常**，支持按类型筛选。

### 12.2 操作

1. **异常类型分布**：各类异常号码数、金额
2. **筛选异常类型** 下拉：超套、零用量、高流量、漫游、离职后计费、资产缺失等
3. 查看 **异常清单明细**（视图 `v_anomaly_list`）

### 12.3 原理

`异常类型` 字段可能是 **多个标签组合**（如「超套;零用量但计费」）。筛选使用「包含」匹配。

### 12.4 使用场景

- 月度对账 **主工作页**：逐条异常闭环
- 导出 Excel 后发给客户确认

## 14. 模块九：事件运营

## 15. 模块十：EMOS 项目配置

### 15.1 功能

为新客户/新项目填写 **项目画像问卷**，系统 **规则匹配** 推荐应落地的 EMOS 组件与服务项，并生成 **落地包**（Markdown/JSON/Excel/Word）。

### 15.2 适用人员

### 15.3 操作（四个 Tab）

4. 点击 **「生成推荐」**

**原理**：画像结构化后，与 `config/emos/` 下组件库、匹配规则比对，得出推荐列表与风险点。

#### Tab ② 组件推荐

查看推荐的服务项、组件列表、风险说明。需先在 Tab① 生成。

#### Tab ③ 落地包导出

1. 选择要导出的格式
2. 生成 **落地包**（含组件清单、流程说明、AI 审查报告等）
3. 下载 Word/Excel 等文件

#### Tab ④ 历史画像

查看、加载以往保存的项目画像。

**侧边栏「同步 EMOS 知识库」**：从 YAML 配置刷新组件库到数据库（管理员/实施人员维护配置后使用）。

## 18. 模块十三：项目差异维护（管理员）

### 18.1 功能

维护 **「标准规则 vs 本项目实际规则」** 差异表，供 Import Gate 与 EMOS 落地包引用。

### 18.2 操作

1. 查看当前所有差异规则
2. **新增/更新**：
   - 作用范围：全局默认（*/*）或指定客户/项目
   - 规则ID、类别、标准规则、本项目规则、确认方等
3. 保存后写入 `config/project_diff.yaml` 并同步 DuckDB
4. 侧边栏 **「立即同步到 DuckDB」** 可手动触发同步

### 18.3 原理

不同客户 Excel 列名、账单结构、匹配逻辑可能不同。差异表让 Gate 和文档生知道「本项目特殊在哪」，而不改核心代码。

**示例**：强生账单双 sheet 合并规则 `BILL-JNJ-001`。

## 20. 模块十五：数据删除（管理员）

### 20.1 功能

删除已导入的测试或正式数据，便于 **重导、清库调试**。

### 20.2 Tab：按项目 / 账期删除

1. 选择客户、项目、账期（可选「删除该项目全部账期」）
2. 选项：
   - 是否删 asset/employee/event（删单账期默认不删）
   - 是否删 `data/raw/` 归档
   - 是否删 `data/output/` 月报
3. 预览 → 输入 `DELETE` → 执行

### 20.3 Tab：按客户删除（全部项目）

1. 选择客户
2. 查看该客户下所有项目/账期汇总
3. 可选删 raw / output
4. 输入 **客户 ID**（如 `johnson`）确认 → 执行

**删除范围**：该客户下全部 raw 表、fact 表、import 报告、meta_project_diff。**不删** EMOS 知识库、账号、YAML 源文件。

### 20.4 使用场景

- 测试环境反复导入
- 导错账期需要整批重来
- 客户合同结束需清库（需管理员审批）

## 21. 常见问题与排查

| 问题 | 可能原因 | 处理 |
|------|---------|------|
| 分析页提示「请回到首页选择客户/项目/账期」 | 侧边栏未选全或账期无数据 | 先导入并 build |
| 导入预检报 `服务号码` 错误 | 账单列名未识别 | 改列名或联系管理员加 `field_maps.yaml` 别名 |
| 首页有数据但超套全为 0 | 资产表缺「标准套餐金额」 | 补资产数据重导 |
| Department/CostCenter 大量为空 | 人员表未导入或未匹配 | 导入 employee，核对员工ID/WWID |
| 导入成功但首页仍无数据 | 未勾选「入库后跑规则引擎」 | 重新导入或 CLI：`tem build --客户 X --项目 Y --账期 Z` |
| 数据删除页 ImportError | Streamlit 缓存旧代码 | 重启 Streamlit；`pip install -e .` |
| 非管理员看不到「数据删除」 | 权限设计 | 用 admin 账号或请管理员操作 |
| EMOS 组件库为空 | 未 bootstrap | 运行 `python scripts/bootstrap_emos_assets.py` 与 `tem sync-emos` |

### 22.2 原始文件目录约定（命令行导入）

```
data/raw/usage/{客户ID}/{项目ID}/{账期}/*.xlsx
data/raw/billing/{客户ID}/{项目ID}/{账期}/*清单*.xlsx
data/raw/billing/{客户ID}/{项目ID}/{账期}/*明细*.xlsx
data/raw/asset/{客户ID}/{项目ID}/*.xlsx
data/raw/employee/{客户ID}/{项目ID}/*.xlsx
data/raw/event/{客户ID}/{项目ID}/*.xlsx
```

### 22.3 常用命令行（与 UI 等价）

```powershell
tem status                                          # 查看各表行数
tem run --客户 johnson --项目 work-phone --账期 202604   # 导入+build+导出
tem build --客户 johnson --项目 work-phone --账期 202604 # 仅跑规则引擎
tem purge --客户 johnson --项目 work-phone --账期 202604 --yes  # 删单账期
tem purge --客户 johnson --delete-raw-files --yes              # 删整个客户
tem sync-diff                                       # 同步项目差异规则
tem sync-emos                                       # 同步 EMOS 知识库
```

### 22.4 配置与客户清单

新客户接入需 IT/管理员编辑 `config/settings.yaml` 的 `clients` 节，例如：

```yaml
clients:
  - 客户ID: johnson
    客户名称: 强生
    projects:
      - 项目ID: work-phone
        项目名称: 工作手机项目
```

保存后重启 Streamlit，导入页下拉框会出现新客户。
