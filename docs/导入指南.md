# 原始数据导入指南

把运营商账单、用量数据和企业资产/人员/事件 5 类数据导入到 TEM 系统的完整步骤。

**两种导入方式**：

| 方式 | 适用场景 | 操作位置 |
|------|---------|---------|
| 🌐 **网页上传**（推荐） | 日常运营、Excel 直接拖拽 | Streamlit 看板侧边栏第一项 **数据导入** |
| 💻 **命令行 + 目录约定** | 批量导入、自动化、CI 接入 | PowerShell `tem run --客户 X --项目 Y --账期 Z` |

两种方式底层调用同一套字段识别与规则引擎，结果完全等价。

---

## 方式 A · 网页直接上传（最简单）

启动看板后，左侧第一个菜单 **数据导入**：

1. 选择客户 / 项目 / 账期（客户下拉来自 [config/settings.yaml](../config/settings.yaml)；项目可手动输入新值）
2. 拖入一个或多个 Excel / CSV 文件 —— 系统会立即扫描表头，识别每个文件属于用量 / 账单 / 资产 / 人员 / 事件中的哪一类
3. 点 **🚀 开始导入**：自动归档到 `data/raw/{type}/{客户ID}/{项目ID}/[{账期}/]`，再调用对应 ingest 入库
4. 勾选"入库后跑规则引擎"会立即生成 `fact_tem_monthly`

识别规则：
- **列名匹配为主**（强信号）：例如出现"事件类型"列 → 事件表；"一级科目"列 → 账单明细
- **文件名兜底**：列名识别失败时，按 `raw_usage_*` / `*用量*` / `*账单*` 这样的关键字猜
- **自动跳过**："事件字典"和"_下拉选项"这样的辅助 sheet 不会入库

下面方式 B 的目录约定、字段映射、常见问题对网页上传也完全适用 —— 因为底层是同一套代码。

---

## 方式 B · 命令行导入（自动化场景）

### 概览

```
真实 Excel  →  data/raw/{type}/{客户ID}/{项目ID}/{账期}/  →  tem run --客户 X --项目 Y --账期 Z  →  fact_tem_monthly  →  看板 + Excel 报表
```

整个过程不需要写任何代码，**只需把文件放到正确目录、运行一条命令**。

---

## 第一步：准备 Excel 文件

### 1.1 列名要求

5 类原始数据各自的字段定义见设计文档第 7~11 章。**列名不需要 100% 一致**，系统会通过 [src/tem/normalize/fields.py](../src/tem/normalize/fields.py) 的别名字典做自动映射。

参考模板已经放在 `data/samples/`，可以直接打开作为字段对照：

| 模板文件 | 对应表 | 必备列（统一字段名） |
|----------|--------|----------------------|
| `01_raw_usage_运营商用量.xlsx` | `raw_usage` | 账期、服务号码、总短信条数、总通话时长_秒、总流量_M |
| `02_raw_billing_账单清单.xlsx` | `raw_billing_list` | 账期、服务号码、用户状态、实际应收 |
| `03_raw_billing_账单明细.xlsx` | `raw_billing_detail` | 账期、服务号码、一级科目、实际应收 |
| `04_raw_asset_资产.xlsx` | `raw_asset` | 服务号码、联系人、邮箱、员工编号、资产状态、标准套餐金额 |
| `05_raw_employee_人员.xlsx` | `raw_employee` | 员工 ID、员工姓名、邮箱、员工状态、BU / Function、Department、Cost Center |
| `06_raw_event_事件总表.xlsx` | `raw_event` | 原始号码、事件类型、事件动作、开始时间、目前状态、使用人WWID |

> 平台通用字段（客户ID、客户名称、项目ID、项目名称、账期、数据来源、导入批次号、数据更新时间）**不需要你在 Excel 里填**，系统按命令行参数自动注入。

### 1.2 文件命名建议（不强制）

| 数据类型 | 推荐文件名包含 | 原因 |
|----------|---------------|------|
| 账单清单 | `清单` 或 `list` | 自动归类到 `raw_billing_list` |
| 账单明细 | `明细` 或 `detail` | 自动归类到 `raw_billing_detail` |
| 事件总表 | `总表` | 多 sheet 时优先取"总表" sheet |
| 其它 | 任意 | — |

文件扩展名支持 `.xlsx` / `.xls` / `.csv`。

## 第二步：把文件放到 data/raw/ 对应目录

### 目录约定

```
data/raw/
├── usage/                              # 运营商用量
│   └── {客户ID}/{项目ID}/{账期}/*.xlsx
├── billing/                            # 运营商账单（清单 + 明细放同一目录）
│   └── {客户ID}/{项目ID}/{账期}/
│       ├── *清单*.xlsx
│       └── *明细*.xlsx
├── asset/                              # 资产管理（按客户/项目全量，无需账期）
│   └── {客户ID}/{项目ID}/*.xlsx
├── employee/                           # 企业人员（按客户/项目全量，无需账期）
│   └── {客户ID}/{项目ID}/*.xlsx
└── event/                              # 月度事件（按客户/项目全量，无需账期）
    └── {客户ID}/{项目ID}/*.xlsx
```

> 资产 / 人员 / 事件 表可以放在项目级目录（不带账期），导入时按命令行参数 `--账期` 标记。
> 用量 / 账单 必须放在账期目录下。

### 实战示例（礼来 / 工作手机 / 2026 年 4 月账期）

1. 看一眼 settings.yaml，找到客户ID 和项目ID：
   ```yaml
   - 客户ID: lilly           # 礼来
     projects:
       - 项目ID: work-phone  # 工作手机项目
   ```

2. 在 PowerShell 里建好目录：
   ```powershell
   cd d:\CursorWorkSpace\诚翼畅联-运营看板项目
   New-Item -ItemType Directory -Force -Path `
     data\raw\usage\lilly\work-phone\202604, `
     data\raw\billing\lilly\work-phone\202604, `
     data\raw\asset\lilly\work-phone, `
     data\raw\employee\lilly\work-phone, `
     data\raw\event\lilly\work-phone
   ```

3. 把 Excel 文件复制（或拖拽）到对应目录：

   ```
   data\raw\usage\lilly\work-phone\202604\联通用量_202604.xlsx
   data\raw\billing\lilly\work-phone\202604\联通账单清单_202604.xlsx
   data\raw\billing\lilly\work-phone\202604\联通账单明细_202604.xlsx
   data\raw\asset\lilly\work-phone\资产清单.xlsx
   data\raw\employee\lilly\work-phone\人员名册.xlsx
   data\raw\event\lilly\work-phone\事件总表.xlsx
   ```

> 你可以把 `data/samples/` 里的 6 个模板**直接拷贝**到上面目录，作为起点。把真实数据粘进去（保留表头），再保存。

## 第三步：跑导入命令

```powershell
cd d:\CursorWorkSpace\诚翼畅联-运营看板项目

# 一键导入 + 规则计算 + 导出 Excel 报表
tem run --客户 lilly --项目 work-phone --账期 202604
```

预期输出（行数会随你的数据量变化）：

```
[run/ingest] usage=850, billing_list=850, billing_detail=3200, asset=820, employee=920, event=18
[run/build] fact_tem_monthly: 850
[run/export] D:\CursorWorkSpace\诚翼畅联-运营看板项目\data\output\lilly_work-phone_202604_TEM月报_20260526xxxxxx.xlsx
```

如果想分步操作：

```powershell
tem ingest --客户 lilly --项目 work-phone --账期 202604               # 只导入
tem ingest --客户 lilly --项目 work-phone --账期 202604 --type usage  # 只导入某一类
tem build  --客户 lilly --项目 work-phone --账期 202604               # 只算规则
tem export --客户 lilly --项目 work-phone --账期 202604               # 只导出报表
tem status                                                            # 查看库内各表行数
```

## 常见问题

### Q1：Excel 里的客户ID / 项目ID 跟我命令行传的不一样会怎样？

命令行参数是 source of truth，会**强制覆盖**所有平台通用字段。这样设计是为了：
- 避免 Excel 里手误打错客户 ID
- 同一份 Excel 可以按不同维度多次导入做对照

如果你想保留 Excel 里的多客户/多项目混合数据，请先按客户 ID / 项目 ID 拆分成多个文件，再分别 `tem ingest`。

### Q2：列名跟模板对不上怎么办？

打开 [src/tem/normalize/fields.py](../src/tem/normalize/fields.py)，找到对应表的别名字典，把真实列名追加进去即可。例如真实账单里"应收金额"列要映射到统一字段"实际应收"：

```python
TABLE_ALIASES = {
    "billing_list": {
        "实际应收": ["实际应收", "应收金额", "本月应收"],  # 在这里追加
        ...
    },
}
```

改完别名字典不需要重启任何服务，重新跑 `tem ingest` 即可。

### Q3：重复导入会怎么样？

`tem ingest` 是**按客户ID + 项目ID + 账期 先删后插**的幂等操作。同一组 (客户, 项目, 账期) 重复导入，旧数据会被新数据覆盖，不会重复。

### Q4：账单明细按号码聚合不一致

设计文档 B04：清单表实际应收合计应与明细表实际应收合计一致。导入后可用 SQL 自查：

```powershell
python -c "from tem.db import connect; con = connect(); print(con.execute('SELECT 服务号码, SUM(实际应收) AS list FROM raw_billing_list WHERE 客户ID = ''lilly'' AND 项目ID = ''work-phone'' AND 账期 = ''202604'' GROUP BY 服务号码').fetchdf().merge(con.execute('SELECT 服务号码, SUM(实际应收) AS detail FROM raw_billing_detail WHERE 客户ID = ''lilly'' AND 项目ID = ''work-phone'' AND 账期 = ''202604'' GROUP BY 服务号码').fetchdf(), on=''服务号码'').query(''abs(list - detail) > 0.01''))"
```

如果有差异，进入异常清单进一步追溯。

### Q5：服务号码有 `.0` 浮点尾巴 / 含 `+86` 前缀

[src/tem/normalize/fields.py](../src/tem/normalize/fields.py) 的 `normalize_phone` 函数已经处理：
- `13800001234.0` → `13800001234`
- `+8613800001234` → `13800001234`
- `8613800001234` → `13800001234`
- ` 13800001234 ` → `13800001234`

无需手工预处理。

### Q6：事件表有多个 sheet（总表 + 套餐变更 + 入职 + 维修 + 离职归还 + 丢失 + 事件字典 + _下拉选项）

按 EV01：第一阶段以"总表"为准。系统会优先读取 sheet 名包含"总表"的 sheet，跳过"事件字典"和"_下拉选项"。

### Q7：账期格式可以是什么？

下列写法都会被识别为 `202604`（YYYYMM）：
- `202604`
- `2026-04`
- `2026/04`
- `2026年4月` / `2026年04月`
- 日期对象（取 yyyymm 部分）

## 多客户 / 多项目并存

每次 `tem run --客户 X --项目 Y --账期 Z` 都只处理一组 (客户, 项目, 账期)。多组数据并存只需重复跑：

```powershell
tem run --客户 lilly      --项目 work-phone --账期 202604
tem run --客户 johnson    --项目 work-phone --账期 202604
tem run --客户 budweiser  --项目 work-phone --账期 202604
tem run --客户 lilly      --项目 work-phone --账期 202605  # 下个月账期
```

看板侧边栏会自动列出所有已分析的客户 / 项目 / 账期，可任意切换。

## 真实数据投递清单（打印贴在工位上）

每月新账期来料后，照下面顺序操作即可：

- [ ] 1. 联通账单清单 Excel  → `data/raw/billing/{客户ID}/{项目ID}/{账期}/*清单*.xlsx`
- [ ] 2. 联通账单明细 Excel  → `data/raw/billing/{客户ID}/{项目ID}/{账期}/*明细*.xlsx`
- [ ] 3. 联通用量 Excel       → `data/raw/usage/{客户ID}/{项目ID}/{账期}/*.xlsx`
- [ ] 4. （若有更新）资产 Excel → `data/raw/asset/{客户ID}/{项目ID}/*.xlsx` **覆盖**
- [ ] 5. （若有更新）人员 Excel → `data/raw/employee/{客户ID}/{项目ID}/*.xlsx` **覆盖**
- [ ] 6. （若有更新）事件 Excel → `data/raw/event/{客户ID}/{项目ID}/*.xlsx` **覆盖**
- [ ] 7. 跑 `tem run --客户 X --项目 Y --账期 YYYYMM`
- [ ] 8. 看板复核 `streamlit run "app/诚翼畅联数据管理平台.py"`
- [ ] 9. 把 `data/output/*_TEM月报.xlsx` 提交给运营经理
